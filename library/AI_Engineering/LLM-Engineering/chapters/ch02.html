The Transformer, Dissected

An exact inventory of what a modern decoder-only LLM computes: every tensor, its shape, its parameters and its arithmetic. Every cost calculation in the rest of the book is built on it.

Why this chapter

Chapter 1 estimated the speed of text generation from just two numbers: the parameter count \(N\) and the memory bandwidth \(\beta\). That estimate was useful, but it treated the model as a black box, and a black box cannot be optimised. To decide whether a technique will help, we need to know where the bytes and operations actually are. Should we shrink the attention layers or the feed-forward layers? Is the vocabulary a significant cost? Exactly how many bytes does each token add to the KV cache, and which design choices control that number? When does the attention computation, ignored in the \(2N\) rule, start to matter?

This chapter answers those questions by taking a modern decoder-only Transformer apart, one component at a time. For each component we ask four questions: why is it there (what problem it solved and when), what does it compute (the mathematics, with shapes), how many parameters does it have, and how many operations does it perform. Along the way we follow how the architecture evolved from 2017 to 2025. Almost every change, from RMSNorm to grouped-query attention, turns out to have been motivated at least partly by cost. We end with exact parameter and FLOP counts for our running examples, checked against published figures. Chapter 3 then uses this inventory to model what it costs to generate text.

2.1 The shape of the computation

From the outside, a language model is a function from a sequence of token ids to a probability distribution over the next token. Inside, the decoder-only Transformer computes it in three stages. First, each token id is replaced by a vector of width \(d\), its embedding. Second, a stack of \(L\) identical blocks transforms these vectors. Each block lets every position gather information from earlier positions (attention) and then transforms each position independently (the feed-forward network). Third, the final vector at each position is mapped to one score per vocabulary entry, the logits, which a softmax turns into probabilities.

The central object is the residual stream: a matrix \(X\in\mathbb R^{T\times d}\) holding one \(d\)-dimensional vector per position. It enters as the embeddings and leaves as the input to the output layer. Every block reads from the residual stream and adds its result back; nothing ever overwrites it. Its shape stays \(T\times d\) (or \(B\times T\times d\) for a batch of \(B\) sequences) from the bottom of the network to the top. This additive structure is what makes very deep networks trainable (§2.6). It also gives a useful mental model: the stream is a shared workspace, and each layer writes small updates into it.

It then passes a second branch that normalises it, applies the feed-forward network and adds that back too. The rest of this chapter explains each box. 2.2 Tokenisation: from text to integers

Before any arithmetic, text must become a sequence of integers, and the choice of units is a real trade-off. Use characters and the vocabulary is tiny, but sequences become long. A thousand-word essay is about 6,000 characters, and every character costs a full forward pass to generate. Use words and sequences are short, but the vocabulary must be enormous to cover names, numbers, typos, code and a hundred languages, and any unseen word is simply unrepresentable. Modern models split the difference with sub-word tokens: frequent words are single tokens, and rare words are spelled out from smaller pieces.

Byte-pair encoding, by hand

The dominant algorithm, byte-pair encoding (BPE), was originally a data-compression scheme and was adapted to neural translation by Sennrich, Haddow and Birch in 2016[3]. Training starts from single characters and greedily builds a vocabulary. Repeatedly find the most frequent pair of adjacent symbols in the corpus, add their concatenation as a new symbol, and replace every occurrence. Stop when the vocabulary reaches the target size. Consider a toy corpus containing the words low (5 times), lower (2), newest (6) and widest (3). The most frequent adjacent pair is e s (9 occurrences, in newest and widest), so es becomes a symbol. Next es t (9) becomes est, then l o (7) becomes lo, then lo w (7) becomes low, and so on. After a few merges, low and est are single tokens, and an unseen word such as lowest is encoded as low + est. The model can represent it, and has a good chance of understanding it. Encoding new text simply replays the learned merges in order.

GPT-2 introduced byte-level BPE, which runs the algorithm over the 256 possible byte values rather than over Unicode characters. Every possible string, in any language, with any emoji or binary junk, is then representable, and no "unknown" token is ever needed. Kudo's Unigram method[4] works in the opposite direction, starting from a large candidate vocabulary and pruning it to maximise the likelihood of the corpus. The SentencePiece library[5] implements both and treats whitespace as an ordinary symbol. Llama 1 and 2, Gemma and T5 use SentencePiece. Llama 3 switched to a byte-level BPE with 128,256 tokens.

What the vocabulary size costs

The table shows vocabularies growing from 32k to more than 250k entries in three years, and the reason is an inference trade-off. A larger vocabulary encodes the same text in fewer tokens. Llama 3's tokeniser uses roughly 15% fewer tokens than Llama 2's for English, and far fewer for many other languages and for code. Fewer tokens means fewer decode steps to write an answer, a proportionally smaller KV cache to hold a conversation, and less attention work. Against that, the two matrices whose size is proportional to \(|\mathcal V|\), the input embedding table and the output projection, become larger. So does the softmax and sampling work at every step. Section 2.3 and the parameter counts in §2.8 quantify that side. For small models it is far from negligible: in Llama 3.2 1B, about a fifth of all parameters are the embedding table.

Production detail — incremental detokenisation

Streaming a reply to the user means converting tokens back to text as they are produced, and this is subtler than it looks. With byte-level BPE, one token can end in the middle of a multi-byte UTF-8 character, such as a Chinese character or an emoji split across two tokens. With SentencePiece, whether a token renders with a leading space depends on the token before it. Servers therefore decode a short sliding window of recent tokens and emit only the newly stable suffix of text. Tokenisation and detokenisation run on the CPU, and at high request rates they can become a measurable bottleneck. This is one reason modern engines move them into separate processes (Chapter 12).

2.3 Embedding and unembedding

Each token id \(x_t\) is mapped to row \(x_t\) of an embedding table \(W_E\in\mathbb R^{|\mathcal V|\times d}\). This is a gather, not a matrix product. It performs no arithmetic and reads only \(d\) numbers per token, so despite holding \(|\mathcal V|\cdot d\) parameters, the embedding table costs almost nothing per token at inference. That is why we exclude it when we count FLOPs in §2.9.

At the top of the stack, the final residual vector \(x\in\mathbb R^{d}\) is normalised and multiplied by the unembedding or LM head \(W_U\in\mathbb R^{d\times|\mathcal V|}\) to produce the logits \(z\in\mathbb R^{|\mathcal V|}\). This is a real matrix product, costing \(2d|\mathcal V|\) operations per token. For Llama 3 8B that is \(2\times4096\times128{,}256\approx 1.05\) billion operations, about 6.5% of the whole forward pass. Press and Wolf showed that tying the two matrices, \(W_U=W_E^\top\), works well and saves \(|\mathcal V|d\) parameters[6]. GPT-2, Gemma and the small Llama 3.2 models tie them; Llama 3 8B and 70B do not.

One observation saves a great deal of work in practice. When a prompt is processed, we need logits only at the last position, because that is where the next token is predicted. An implementation that applies the LM head to every prompt position wastes \(2d|\mathcal V|\) operations per extra position and builds a \(T\times|\mathcal V|\) tensor that can run to gigabytes. Chapter 3 returns to this.

2.4 Attention: a differentiable dictionary

Why do we need attention at all? Each position's vector must be able to draw on information from earlier positions. In "The trophy did not fit in the suitcase because it was too big", the representation of "it" needs to retrieve information about "trophy". The RNN of Chapter 1 did this by compressing everything into one state vector. Attention instead lets each position look up what it needs from all earlier positions directly.

The cleanest way to understand attention is as a soft dictionary lookup. An ordinary dictionary holds key–value pairs, and a query retrieves the value whose key matches it exactly. In attention, every earlier position \(j\) offers a key \(k_j\) (what it is about) and a value \(v_j\) (what it can contribute). The current position \(i\) issues a query \(q_i\) (what it is looking for). Instead of an exact match, the query is compared with every key by an inner product, the scores are turned into weights by a softmax, and the result is the weighted average of the values. Because every step is differentiable, the model can learn what to put in queries, keys and values.

Concretely, let \(\tilde X\in\mathbb R^{T\times d}\) be the normalised residual stream of one sequence. A single attention head has projections \(W_Q,W_K,W_V\in\mathbb R^{d\times d_h}\) and computes

\[ Q = \tilde XW_Q,\quad K = \tilde XW_K,\quad V = \tilde XW_V \;\in\mathbb{R}^{T\times d_h}, \] \[ S = \frac{QK^\top}{\sqrt{d_h}} + M \in\mathbb{R}^{T\times T},\qquad P = \operatorname{softmax}_{\text{row}}(S), \qquad O = PV\in\mathbb{R}^{T\times d_h}, \]

where the causal mask is \(M_{ij}=0\) if \(j\le i\) and \(-\infty\) otherwise. Row \(i\) of \(P\) is a probability distribution over positions \(1,\dots,i\), and row \(i\) of \(O\) is the corresponding convex combination of value vectors. The mask is what makes the model autoregressive. Position \(i\) cannot see the future, so the prediction it makes for position \(i+1\) is a genuine prediction.

Why divide by \(\sqrt{d_h}\)?

Suppose the coordinates of \(q\) and \(k\) are independent, with mean 0 and variance 1. This is roughly true at initialisation, because the input is normalised. Then \[ \mathbb{E}[q\cdot k] = 0,\qquad \operatorname{Var}(q\cdot k) = \sum_{c=1}^{d_h}\operatorname{Var}(q_c k_c) = \sum_c \mathbb{E}[q_c^2]\,\mathbb{E}[k_c^2] = d_h . \] Unscaled scores would therefore have a standard deviation of \(\sqrt{d_h}\), about 11 for \(d_h=128\). A softmax of numbers that differ by tens is essentially one-hot. Its Jacobian, \(\operatorname{diag}(p)-pp^\top\), is then nearly zero, so gradients vanish and learning stalls. Dividing by \(\sqrt{d_h}\) restores unit variance, so attention starts out diffuse and trainable. Some recent models go further with QK-norm, an RMSNorm applied to queries and keys, to keep scores bounded throughout training.

Many heads

One head computes one pattern of attention, but a position may need several kinds of information at once: the previous token, the subject of the sentence, a matching bracket. Multi-head attention runs \(n_h\) heads in parallel, each with its own projections into a smaller space of dimension \(d_h=d/n_h\). The head outputs are concatenated and mixed by an output projection:

\[ \operatorname{MHA}(\tilde X) = \big[O^{(1)};\dots;O^{(n_h)}\big]\,W_O,\qquad W_O\in\mathbb{R}^{n_hd_h\times d}. \]

In implementations the \(n_h\) query projections are a single \(d\times n_hd_h\) matrix. Its output is reshaped to \((T, n_h, d_h)\) and transposed to \((n_h, T, d_h)\), so heads behave like an extra batch dimension. Interpretability research has found heads specialising in strikingly specific roles, such as copying the previous token or completing repeated patterns ("induction heads")[7].

Figure 2.2 traces the data flow with shapes. The input \(X\) of shape \((T,d)\) is projected three ways. The scores \(S\) and probabilities \(P\) are \((n_h, T, T)\): one \(T\times T\) matrix per head, which is why attention's cost grows quadratically with sequence length. Two matrix products dominate the arithmetic, \(QK^\top\) and \(PV\), each costing \(2n_hT^2d_h\) operations. Notice that \(K\) and \(V\) are drawn with \(n_{kv}\) heads rather than \(n_h\). That is the next idea.

Sharing keys and values: MHA → MQA → GQA

In the original design every head has its own keys and values, so \(n_{kv}=n_h\). For training this is harmless. During generation, however, Chapter 1 explained that the keys and values of all previous tokens must be kept in the KV cache and read in full at every step. In 2019 Noam Shazeer measured that this reading, not arithmetic, was what limited decoding speed. He proposed multi-query attention (MQA), in which all \(n_h\) query heads share a single key head and a single value head[8]. The cache shrinks by a factor of \(n_h\), and the queries are untouched, so heads can still attend in different ways. MQA cost some quality and occasionally destabilised training. In 2023 Ainslie et al. proposed the interpolation that is now standard, grouped-query attention (GQA)[9]. There are \(n_{kv}\) key/value heads, each shared by a group of \(g=n_h/n_{kv}\) query heads. Both our running examples use GQA with \(n_{kv}=8\): \(g=4\) for Llama 3 8B and \(g=8\) for Llama 3 70B. DeepSeek's multi-head latent attention (MLA) (2024)[10] goes further, caching a compressed latent vector from which keys and values are reconstructed; Chapter 8 derives it.

Figure 2.3 shows the three designs with four query heads each. With MHA there is one cached key/value head per query head. GQA (here with \(g=2\)) halves the cache, and MQA quarters it. The query side, and hence the attention arithmetic, is identical in all three. The savings are purely in memory and memory traffic, which in Chapter 3 will turn out to be exactly what decode is limited by.

2.5 Where am I? Positional information

Attention as defined so far has a blind spot. It compares contents, but it has no notion of order.

Proposition — attention without positions is permutation-equivariant

Drop the causal mask and let \(\Pi\) be a permutation matrix. Replacing \(\tilde X\) by \(\Pi\tilde X\) replaces \(Q,K,V\) by \(\Pi Q,\Pi K,\Pi V\), so \(S\) becomes \(\Pi S\Pi^\top\). A row-wise softmax commutes with permuting rows and columns together, so \(P\) becomes \(\Pi P\Pi^\top\). The output is \(\Pi P\Pi^\top\Pi V = \Pi PV = \Pi O\). Permuting the input merely permutes the output, so the model cannot distinguish "dog bites man" from "man bites dog". ∎

The causal mask breaks this symmetry partially, since position \(i\) sees exactly \(i\) tokens. Models with no explicit positional signal ("NoPE") can learn some order from it, but explicit encodings work better. The field tried four approaches in turn. The original Transformer added fixed sinusoidal vectors to the embeddings, \(\mathrm{PE}_{(t,2r)}=\sin(t/10000^{2r/d})\) and \(\mathrm{PE}_{(t,2r+1)}=\cos(t/10000^{2r/d})\). GPT-2 and BERT learned a table of position vectors, which cannot represent positions beyond the table's length. ALiBi (2021)[11] abandoned position vectors and instead subtracted a head-specific linear penalty \(\lambda\,(i-j)\) from each score, so distant tokens are attended to less. The approach that won, and that nearly every model since LLaMA uses, is the rotary position embedding (RoPE)[12].

RoPE, properly

RoPE starts from a wish. We would like the score between a query at position \(i\) and a key at position \(j\) to depend on their contents and on the offset \(i-j\), but not on where the pair sits in the sequence. Rotations deliver exactly this. Split \(q\in\mathbb{R}^{d_h}\) into \(d_h/2\) coordinate pairs, and view pair \(r\) as a complex number \(\tilde q_r = q_{2r} + \mathrm{i}\,q_{2r+1}\). Choose a frequency for each pair, \(\theta_r = \Theta^{-2r/d_h}\) for \(r=0,\dots,d_h/2-1\), where the base \(\Theta\) is \(10^4\) in LLaMA and \(5\times10^5\) in Llama 3. RoPE rotates pair \(r\) of a vector at position \(i\) by the angle \(i\theta_r\):

\[ \operatorname{RoPE}(q, i)_r = \tilde q_r\, e^{\mathrm{i}\, i\theta_r} \quad\Longleftrightarrow\quad \begin{pmatrix} q'_{2r}\\ q'_{2r+1}\end{pmatrix} = \begin{pmatrix}\cos i\theta_r & -\sin i\theta_r\\ \sin i\theta_r & \cos i\theta_r\end{pmatrix}\begin{pmatrix} q_{2r}\\ q_{2r+1}\end{pmatrix}. \]

(Here the upright \(\mathrm{i}\) is the imaginary unit and the italic \(i\) is the position.) The same rotation is applied to keys, but not to values.

Theorem — RoPE scores depend only on relative position

For a query at position \(i\) and a key at position \(j\), \[ \big\langle \operatorname{RoPE}(q,i), \operatorname{RoPE}(k,j)\big\rangle = \operatorname{Re}\sum_r \tilde q_r e^{\mathrm{i}\,i\theta_r}\,\overline{\tilde k_r e^{\mathrm{i}\,j\theta_r}} = \operatorname{Re}\sum_r \tilde q_r\,\overline{\tilde k_r}\,e^{\mathrm{i}(i-j)\theta_r}. \] Equivalently, if \(R_i\) is the block-diagonal matrix of \(2\times2\) rotations, then \(R_i^\top R_j=R_{j-i}\), because the rotations in each plane form a group. The score depends on \(q\), \(k\) and \(i-j\) only. ∎

Figure 2.4 makes the theorem visual. On the left, one coordinate pair of a query and a key is drawn in its plane, separated by the angle \((j-i)\theta_r\). On the right, both positions have been shifted by the same amount \(s\). Both vectors rotate by \(s\theta_r\), the angle between them is unchanged, and so is their inner product. Low-index pairs have large \(\theta_r\) and rotate quickly, so they are sensitive to small offsets. High-index pairs rotate slowly and can encode long-range offsets. Raising the base \(\Theta\) slows every rotation, and the techniques that stretch a model's context window (position interpolation, NTK scaling, YaRN; Chapter 21) work by rescaling these frequencies.

Inference consequence — the cache stores rotated keys

Inference engines apply RoPE to each key before storing it in the KV cache, so the rotation is computed once rather than at every step. A cached key is therefore bound to its absolute position. Two consequences recur later in the book. Prefix caching (Chapter 10) can reuse cached keys only for a prefix that appears at the same positions. And any technique that drops or moves tokens within the cache (Chapter 8) must either re-rotate the affected keys or tolerate gaps in the positions. DeepSeek's MLA keeps a small separate rotated key for precisely this reason: rotation does not commute with its low-rank compression.

2.6 The residual stream and normalisation

Deep networks are hard to train because signals and gradients must pass through many layers, a multi-layer version of the RNN's vanishing-gradient problem (§1.4). The Transformer uses two remedies: residual connections, which give every layer an identity path, and normalisation, which keeps the scale of activations under control. Where exactly the normalisation sits turned out to matter a great deal.

LayerNorm[13] normalises each token's vector to zero mean and unit variance, then applies a learned scale and shift: \(\operatorname{LN}(x) = \gamma\odot(x-\mu)/\sqrt{\sigma^2+\epsilon}+\delta\), where \(\mu\) and \(\sigma^2\) are the mean and variance of the \(d\) coordinates and \(\gamma,\delta\) are learned. Zhang and Sennrich observed that the centring step contributes little and proposed RMSNorm[14], which only rescales:

\[ \operatorname{RMSNorm}(x) = \gamma\odot \frac{x}{\sqrt{\tfrac{1}{d}\sum_{c=1}^{d} x_c^2+\epsilon}} . \]

RMSNorm needs one reduction instead of two and has no shift parameter. Llama-family models use it. Both norms are trivial in FLOPs but are memory-bound: their cost is the time to read and write the activations, which is why engines fuse "add the residual, then normalise" into a single GPU kernel (Chapter 7).

The original Transformer placed the norm after the residual addition, \(x\leftarrow\operatorname{LN}(x+F(x))\) for a sub-layer \(F\) ("Post-LN"). Xiong et al. showed that this makes gradients near the output large at initialisation, which is why the original model needed a careful learning-rate warm-up[15]. Moving the norm inside the branch, \(x\leftarrow x + F(\operatorname{Norm}(x))\) ("Pre-LN"), leaves an untouched identity path from input to output. That path is the residual stream of §2.1, and training becomes stable without delicate warm-up.

Figure 2.5 contrasts the two placements. In Post-LN (left) the main path passes through a normalisation in every layer. In Pre-LN (right) the main path, drawn in blue, is a pure sum of the input and every sub-layer's output. One consequence is easy to miss: since the residual stream is never normalised inside the blocks, every Pre-LN model needs one final normalisation before the LM head, the "final RMSNorm" in Figure 2.1. Some 2024–25 models (Gemma 2 and 3, OLMo 2) add further norms after sub-layers as well.

2.7 The feed-forward network: where most parameters live

After attention has gathered information across positions, the feed-forward network (FFN) transforms each position independently. If attention is communication, the FFN is computation. Geva et al. offered an illuminating reading: the first matrix's columns act as keys that detect patterns in the residual stream, and the second matrix's rows act as values that write associated information back. The FFN is thus a large associative memory[16]. That is consistent with where the parameters are: about two-thirds of a dense model's non-embedding parameters sit in its FFNs.

The original FFN is a two-layer perceptron, \(\operatorname{FFN}(x)=\max(0, xW_1)W_2\), with hidden width \(4d\). GPT-2 and BERT replaced the ReLU with the smoother GELU[17]. In 2020 Shazeer tested gated variants, in which one projection multiplicatively gates another, and found them consistently better at equal cost[18]. The winner, used by PaLM, LLaMA and nearly every model since, is SwiGLU:

\[ \operatorname{SwiGLU}(x) = \big(\operatorname{SiLU}(xW_1)\odot xW_3\big)W_2,\qquad \operatorname{SiLU}(u)=u\,\sigma(u),\quad W_1,W_3\in\mathbb{R}^{d\times d_{ff}},\ W_2\in\mathbb{R}^{d_{ff}\times d}. \]

SwiGLU has three matrices instead of two. To keep the parameter count equal to a \(4d\)-wide two-matrix FFN (\(2\times4d^2=8d^2\)), set \(3dd_{ff}=8d^2\), that is \(d_{ff}=\tfrac83 d\). LLaMA-7B used \(d_{ff}=11008\), which is \(\tfrac83\times4096\) rounded up to a multiple of 256. Llama 3 8B widened it to \(14336=3.5d\). At inference, \(W_1\) and \(W_3\) are usually fused into a single \(d\times 2d_{ff}\) matrix product, followed by one fused "SiLU-and-multiply" kernel. Because the FFN holds most of the weights, it is also where weight quantisation pays off most (Chapter 14), and it is the component that Mixture-of-Experts models replace with many smaller experts (Chapter 19).

2.9 Counting parameters

With every component defined, we can count. Write \(d_{kv}:=n_{kv}d_h\) for the total width of the keys (and of the values). One block contains

\[ \underbrace{d\cdot d}_{W_Q} + \underbrace{2\,d\,d_{kv}}_{W_K,\,W_V} + \underbrace{d\cdot d}_{W_O} + \underbrace{3\,d\,d_{ff}}_{W_1,W_2,W_3} + \underbrace{2d}_{\text{two norms}} \]

parameters, assuming \(n_hd_h=d\) as in all our examples. Adding the embedding table, the LM head (if not tied) and the final norm:

\[ N = L\big(2d^2 + 2\,d\,d_{kv} + 3\,d\,d_{ff} + 2d\big) + |\mathcal V|\,d\,\big(1 + [\text{untied}]\big) + d . \]

Rule of thumb for multi-head attention with a two-matrix \(4d\) FFN: \(N\approx 12Ld^2\), that is \(4d^2\) for attention and \(8d^2\) for the FFN per layer.

Worked example — Llama 3 8B

Here \(d_{kv}=8\times128=1024\). Attention per layer: \(2\times4096^2 + 2\times4096\times1024 = 33.55\text{M}+8.39\text{M}=41.94\)M. FFN per layer: \(3\times4096\times14336=176.16\)M. With the two norms (8,192), one layer has 218.11M parameters, and 32 layers have 6.980B. The untied embedding and LM head add \(2\times128{,}256\times4096=1.051\)B. Total ≈ 8.03B, matching the published figure. Note the proportions. The FFNs hold 70% of the parameters and attention only 17%, and the vocabulary matrices are a substantial 13%. GQA cut attention's parameters by 37% compared with full multi-head attention (\(4d^2=67.1\)M per layer).

2.10 Counting FLOPs

Parameters tell us how many bytes must be stored and, in decode, read. Floating-point operations (FLOPs) tell us how much arithmetic must be done. Both are needed, because Chapter 3 will show that the speed of each phase is set by whichever of the two limits binds first.

The fundamental counting rule

Multiplying \(A\in\mathbb{R}^{m\times k}\) by \(B\in\mathbb{R}^{k\times n}\) computes \(mn\) dot products of length \(k\). That is \(mnk\) multiplications and \(mn(k-1)\approx mnk\) additions. We count \(2mkn\) FLOPs. Hardware vendors also count a fused multiply-add as two FLOPs, so these counts can be compared directly with datasheet peaks.

Apply the rule to a weight matrix \(W\in\mathbb{R}^{k\times n}\) acting on \(m\) token vectors: \(2mkn\) FLOPs, that is two FLOPs per parameter per token. Summing over every weight matrix in the model gives the famous rule. To it we must add the one part of the computation that does not involve weights, the attention scores and the weighted sum of values. For a query at position \(t\), each head computes \(t\) dot products of length \(d_h\) (\(2td_h\) FLOPs) and a weighted sum of \(t\) value vectors (another \(2td_h\)). Over \(n_h\) heads and \(L\) layers this is \(4Ln_hd_ht=4Ldt\). Hence:

\[ C_{\text{forward}} \approx 2N_{\text{mm}} + 4\,L\,d\,t\quad\text{FLOPs per token at position }t, \]

where \(N_{\text{mm}}\) counts the parameters used in matrix products: all of them except the embedding table, which is a lookup. For Llama 3 8B, \(N_{\text{mm}}\approx 8.03-0.53=7.50\)B.

Two remarks. First, GQA does not reduce the attention term: every query head still attends over every position. GQA saves memory and memory traffic, not arithmetic. Second, the formula is per token, so a forward pass over a whole prompt of \(T\) tokens costs about \(2N_{\text{mm}}T + 2LdT^2\), since the attention term summed over positions \(1,\dots,T\) gives \(4Ld\cdot T^2/2\).

When does attention matter?

Is the attention term significant? Compare it with the weight term. For a model with \(N\approx12Ld^2\), the ratio is

\[ \frac{4Ldt}{2\cdot12Ld^2} = \frac{t}{6d}. \]

The attention arithmetic equals the weight arithmetic at a context of about \(6d\) tokens, roughly 24,600 for \(d=4096\). Below a few thousand tokens, "\(2N\) FLOPs per token" is accurate to a few percent. At the 128k-token contexts that modern models support, attention dominates. Llama 3 8B's wide FFN gives it more weight FLOPs than the rule of thumb assumes, so its crossover is slightly later, at \(2N_{\text{mm}}/(4Ld) = 15.0\times10^{9}/524{,}288\approx 28{,}600\) tokens.

Figure 2.7 draws this for Llama 3 8B. The weight term is a flat line at 15 GFLOPs per token. The attention term rises linearly and crosses it near 28.6k tokens. By the end of a 128k-token context, attention is more than four times the weight cost, and the token costs more than five times what the \(2N\) rule predicts. This growth explains much of the long-context research of Chapters 9 and 21.

Why training costs \(6N\)

Chapter 1 used \(C\approx6ND\) for training. Now we can derive it. For a linear layer \(Y = XW\) with \(X\in\mathbb{R}^{m\times k}\), the forward pass costs \(2mkn\). Back-propagation needs the gradient with respect to the input, \(\partial\mathcal L/\partial X = (\partial\mathcal L/\partial Y)\,W^\top\), and with respect to the weights, \(\partial\mathcal L/\partial W = X^\top(\partial\mathcal L/\partial Y)\). Each is a matrix product of the same size as the forward one, another \(2mkn\) each. Total: \(6mkn\), or \(2+4=6\) FLOPs per parameter per token. If activations are recomputed during the backward pass to save memory, the total rises to about \(8ND\).

Looking ahead

We now have a complete inventory. We know every tensor and its shape, how many parameters each component holds (mostly FFN, then attention, then the vocabulary), how many FLOPs a token costs (\(2N_{\text{mm}}\) plus an attention term that grows with context), and how many bytes the weights occupy. What we have not yet done is run the model. Generating text calls this computation once per token, carrying a growing KV cache from call to call. Chapter 3 turns the inventory into a cost model of generation. It proves that caching is exact and measures the cache, explains why reading a prompt is compute-bound while writing an answer is memory-bound, and predicts the time to first token and the time per output token of a real request.

Chapter summary

  • A decoder-only Transformer has an embedding lookup, \(L\) Pre-norm blocks of the form \(x\leftarrow x+\operatorname{Attn}(\operatorname{Norm}(x))\) and \(x\leftarrow x+\operatorname{FFN}(\operatorname{Norm}(x))\), a final norm and an LM head. The residual stream keeps shape \(T\times d\) throughout.

  • Attention is a differentiable dictionary lookup. Dividing by \(\sqrt{d_h}\) keeps scores at unit variance. MQA and GQA share keys and values across query heads to shrink the KV cache without changing the arithmetic.

  • \(N = L(2d^2+2dd_{kv}+3dd_{ff}+2d)+|\mathcal V|d(1+[\text{untied}])+d\). Llama 3 8B ≈ 8.03B and Llama 3 70B ≈ 70.6B.

Warm-up Why do we divide attention scores by \(\sqrt{d_k}\)?

Core What does GQA buy you, and what does it cost?

Buys: KV cache and its bandwidth shrink by \(g=n_h/n_{kv}\) (4× for Llama 3 8B, 8× for 70B); decode attention intensity rises from 1 to \(g\) FLOPs/byte; more concurrent sequences fit; K/V projection parameters shrink; with tensor parallelism, KV heads are naturally partitioned across GPUs (as long as TP ≤ \(n_{kv}\); beyond that KV heads must be replicated). Core Explain RoPE and prove its relative-position property.

RoPE groups the \(d_h\) coordinates of a query or key into \(d_h/2\) pairs, treats pair \(r\) as a complex number, and multiplies it by \(e^{\mathrm{i}\,i\theta_r}\) at position \(i\), with \(\theta_r=\Theta^{-2r/d_h}\). Then \(\langle\mathrm{RoPE}(q,i),\mathrm{RoPE}(k,j)\rangle=\operatorname{Re}\sum_r\tilde q_r\overline{\tilde k_r}e^{\mathrm{i}(i-j)\theta_r}\), which depends only on \(i-j\). In matrix form, \(R_i\) is block-diagonal with \(2\times2\) rotations and \(R_i^\top R_j=R_{j-i}\). Advantages: no learned parameters, relative-position behaviour inside attention, and it is defined for any length, although quality beyond the training length needs frequency rescaling (PI, NTK, YaRN). Inference notes: it is applied to \(q\) and \(k\) only, not \(v\); it is applied before keys are cached, so cached keys are tied to absolute positions; and it is usually fused into the QKV projection or attention kernel.

Core Why does the LM head deserve special attention in inference engines?

(1) Size: \(d\times|V|\) is the largest single matrix in many modern models (Llama 3 8B: 525M parameters, 1.05 GB in BF16), and it is read every decode step. (2) Compute: \(2d|V|\) FLOPs/token (~6.5% of Llama 3 8B). (3) Prefill waste: compute logits only for the last position (or positions where log-probs are requested), saving a \(T\times|V|\) activation that could be gigabytes. (4) Sampling: softmax and top-k/top-p over 128k–256k logits per sequence need efficient GPU kernels. (5) Parallelism: with tensor parallelism the head is split along the vocabulary dimension, requiring a gather or a distributed argmax/sampling. (6) Speculative decoding and MTP heads often share it.

Deep-dive Why did the field move from ReLU FFNs to SwiGLU, and what are the inference implications?

Shazeer (2020) found gated variants (GEGLU, SwiGLU) give lower perplexity at equal parameters and compute; LLaMA/PaLM adopted SwiGLU. A gate multiplies two linear projections, providing multiplicative interactions and smoother activations. Inference: (1) three matrices instead of two—\(W_1\) and \(W_3\) are typically fused into one \(d\times2d_{ff}\) GEMM, followed by a fused SiLU-and-multiply kernel; (2) with \(d_{ff}=\tfrac83 d\) parameter count matches the old FFN so FLOPs/token are unchanged; (3) activation sparsity is lower than with ReLU, weakening "sparse activation" speed-ups (Deja Vu, PowerInfer) unless models are "ReLU-fied"; (4) the FFN dominates weight bytes, so it is where weight quantisation and MoE give the largest gains.

Warm-up What is the difference between the residual stream and the hidden size, and why does it matter for tensor parallelism?

The residual stream is the \(d\)-dimensional vector per token that flows through all blocks and accumulates sub-layer outputs (\(x\leftarrow x+f(\mathrm{Norm}(x))\)); "hidden size" is its width \(d\). Sub-layers temporarily expand into other spaces (\(n_hd_h\) for attention, \(d_{ff}\) for the FFN) and project back to \(d\). Tensor parallelism (Megatron) splits those expanded spaces across GPUs—column-parallel first matrix, row-parallel second—so each GPU holds a slice of heads or FFN columns, and an all-reduce over the \(d\)-dimensional output re-forms the residual stream after each sub-layer: two all-reduces of \(B\times T\times d\) per block (Chapter 17).

Warm-up How does byte-pair encoding work, and why do modern LLMs use sub-word tokens rather than characters or words?

BPE starts from characters (or bytes), repeatedly merges the most frequent adjacent pair of symbols into a new symbol, and stops at a target vocabulary size. Encoding replays the merges in order. Sub-words balance two failure modes. Characters give tiny vocabularies but very long sequences, and every token costs a forward pass to generate and a KV-cache entry to store. Words give short sequences but need enormous vocabularies and cannot represent unseen words. With sub-words, common words are single tokens and rare words are composed from pieces. Byte-level BPE (GPT-2 onward) uses the 256 bytes as the base alphabet, so any string is representable without an unknown token.

Core You are designing a 1B-parameter on-device model. Would you choose a 32k or a 256k vocabulary? Discuss the trade-off quantitatively.

For \(d\approx2048\), a 256k vocabulary has an embedding matrix of 524M parameters, about half of a 1B model (and double that if untied), while a 32k vocabulary costs 65M. The larger vocabulary shortens sequences, perhaps by 20–40% for multilingual text or code, which reduces decode steps, KV cache and attention. But it costs model capacity, memory (crucial on device) and per-step LM-head FLOPs and sampling cost (\(2d|\mathcal V|\) per token). For a small, mostly English model, a moderate vocabulary (32k–64k) with tied embeddings is usually preferable. If multilingual coverage or code matters, a larger vocabulary can pay for itself through shorter sequences. In either case the choice should be measured as bits per byte and tokens per second on the target workload.

Core Why did Pre-LN replace Post-LN, and why did RMSNorm replace LayerNorm?

Placement: Post-LN normalises the sum \(x+F(x)\), so the residual path itself passes through a normalisation in every layer. Xiong et al. (2020) showed that gradients near the output are then large at initialisation, so training needs a carefully tuned warm-up and can diverge at depth. Pre-LN, \(x+F(\operatorname{Norm}(x))\), keeps a clean identity path from input to output and trains stably; it needs a final norm before the LM head. Type: RMSNorm drops LayerNorm's mean subtraction and bias. Empirically the centring contributes little, and RMSNorm needs one reduction instead of two. At inference both are memory-bound, so the practical point is to fuse them with the residual addition.

Core Derive the 6N training-FLOPs rule from first principles.

For a linear layer \(Y=XW\) with \(X\in\mathbb R^{m\times k}\) and \(W\in\mathbb R^{k\times n}\), the forward pass is one matrix product: \(2mkn\) FLOPs, that is 2 per parameter per token. The backward pass needs \(\partial\mathcal L/\partial X=(\partial\mathcal L/\partial Y)W^\top\), to propagate to earlier layers, and \(\partial\mathcal L/\partial W=X^\top(\partial\mathcal L/\partial Y)\), for the update. Each is a product of the same dimensions, another \(2mkn\) each. Total \(6mkn\), so \(6N\) per token and \(C\approx6ND\). Caveats: attention-score FLOPs add a sequence-length-dependent term; activation recomputation adds a second forward pass (≈ \(8N\)); the optimiser update is \(O(N)\) per step, not per token, and so negligible.

Deep-dive Explain the "soft dictionary" view of attention and the "key–value memory" view of the FFN. How do they differ in what they store?

Attention: each position emits a query; every earlier position offers a key and a value computed from the current context. The output is a softmax-weighted average of values, a differentiable lookup into a dictionary that is built on the fly from the sequence. Its contents are therefore dynamic and per-sequence, and at inference they are exactly what the KV cache stores. The FFN (Geva et al. 2021): the rows of \(W_1\) act as keys matched against the residual vector, the activation pattern selects among them, and the rows of \(W_2\) are values written back. Its contents are static parameters learned during training, a memory of knowledge shared across all inputs. The serving consequence is that FFN memory costs bytes of weights (amortised across a batch), while attention memory costs bytes of cache (per sequence, not amortisable). That asymmetry drives Chapter 3.

Deep-dive When does the attention term invalidate the "2N FLOPs per token" rule? Give numbers for Llama 3 8B.

Per token at position \(t\), attention adds \(4Ldt\) FLOPs to the weight cost \(2N_{\text{mm}}\). For Llama 3 8B, \(4Ld=4\times32\times4096=524{,}288\) FLOPs per token of context, and \(2N_{\text{mm}}\approx15.0\) GFLOPs. They are equal at \(t\approx28.6\)k. At 4k context attention adds ≈ 14%, and at 128k it adds ≈ 4.6× (total ≈ 84 GFLOPs per token). For a whole prompt of \(T\) tokens the attention cost is \(2LdT^2\), quadratic, so a 128k-token prefill costs ≈ \(2\times10^{15}\) FLOPs for weights plus ≈ \(4.5\times10^{15}\) for attention. This is why long-context prefill motivates FlashAttention, context parallelism and sparse attention. Note that GQA does not change these numbers; it only reduces memory traffic.

Design Given only a model's config.json and the storage dtype, list every quantity you can compute and how.
  • Parameters: \(N=L(2d^2+2dd_{kv}+3dd_{ff}+2d)+|\mathcal V|d(1+[\text{untied}])+d\), adjusted for biases or MoE (experts × FFN, plus router).
  • Weight bytes: \(Nb\), which decides how many GPUs are needed.
  • FLOPs per token: \(2N_{\text{mm}}+4Ldt\); for prefill \(2N_{\text{mm}}T+2LdT^2\).
  • KV-cache bytes per token: \(2Ln_{kv}d_hb_{kv}\) (Chapter 3), which decides maximum concurrency.
  • Context limit and RoPE base: from max_position_embeddings and rope_theta.
  • With a GPU spec (Chapter 3): decode step ≈ bytes ÷ bandwidth, prefill ≈ FLOPs ÷ peak, and the crossover batch size.
